## 2. Profile tab connected to V2

**Why it showed "25% / Complete Profile":**
- The old badge (`computeProfileCompletion` in `app/(tabs)/profile.tsx`) scored 8 V1 `profiles` columns: bio, hobbies, favorite_*, availability_days, languages, photo_verified, plus "≥1 photo" and "≥3 photos".
- A V2 member's answers live in the V2 tables. Only the photo count (copied to `profiles.photos` at acceptance) matched → 2/8 = 25%.

**Change:**
- Approved V2 members (server gate `member`) now get `components/main/V2ProfileHome.tsx`:
    - main photo (signed private URL), first name in Playfair;
    - real saved counts: **Photos N of 6**, **Prompts N of 3** (answered);
    - **View profile** → new `app/v2/profile.tsx`: the approved V2 profile view, i.e. `get_profile_v2`, exactly what others see;
    - **Edit profile** (see below);
    - Sign out.
- No percentage, no fake 100%, no "missing" items.
- V1 accounts keep the old screen unchanged.

**Editing after approval — open decision, nothing invented:**
- The server locks answers once an application is sent (`v2_assert_editable`: only `draft` / `changes_requested` may edit).
- No decision exists on member edits or re-review.
- So **Edit profile is disabled**, with "Editing after approval isn't available yet."
- **No path reaches the V1 editor any more** for a V2 member:
    - the Settings rows "Edit profile", "Photos" and the V1 "Languages" card are hidden;
    - `/profile-edit` itself shows the same notice.

## 5. Match strategy — current conflicts (for the next work package, nothing changed)

Target: mutual match → chat → a meetup suggestion when a user wants one → the other side accepts. No separate "Ready to meet" stage, no auto pop-up, no 5-message / 24 h threshold.

**Already in line:**
- A mutual like opens the chat at once (`handle_mutual_like`).
- The chat has a user-initiated "Suggest a meetup" with propose / accept / suggest-another (`matches.meetup_proposed_by` / `meetup_confirmed`).
- `shouldOpenChatOnAccept` is always true.

**Conflicts:**
1. **Matches "Ready" cards:** the primary action is **"Plan a date"** (`micro-intro.tsx`). The algorithmic candidate gets a date invitation *before* any mutual match or chat; the chat opens only after the invite is accepted. This is the opposite order.
2. **Matches is not V2-aware:**
    - candidates still come from V1 `get_top_matches` with a **compatibility %** (`MatchScoreBadge`, `match_score`);
    - they are not from V2 eligibility;
    - V2 Discover shows no score. The two tabs disagree.
3. **Plans tab** ("Waiting for them" / "Invitations for you") and Activity's "wants to meet" cards with time chips belong to the invite-first funnel, not to a chat-originated suggestion.
4. **Daily invite quota** (`try_send_invite`, 1 or 3 a day) gates the invite-first flow. Its role in the target flow is undecided.
5. **Chat meetup bar wording:** code comments still describe it as "mutual-like only", although it is enabled for every open chat. This needs a check that it never auto-prompts (it is a persistent bar, not a pop-up — keep it that way).
6. **Push / notifications:** `send-push-notification` and `handle_match_notification` key on `invited_by` (invites). Mutual-like matches have no push.

The Matches / Ready / Plans tab names were not changed.
