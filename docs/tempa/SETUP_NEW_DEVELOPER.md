# Tempa — setting up as a new developer (2026-10-27)

> **Not verified on a clean machine.** These steps are put together from the repo and the owner's working setup. Nobody has run them end to end on a fresh Mac yet. Record what differs when you do.

Branch for the V2 product: `tempa/v2-persist-r2`. It is **not merged into `main`**: `main` has 2 doc-only commits this branch doesn't have, and this branch is far ahead of `main`. Nothing here is released or deployed.

| Tool | Version | Notes |

## 3. Your own local backend (tempa-local)

You need **your own** local Supabase. The owner's tempa-local runs only on the owner's Mac (`127.0.0.1:55421`). It is not reachable from your computer: there is no tunnel, no shared host, and the scripts refuse non-local addresses.

1. `node scripts/local-backend/setup.mjs`
   - Generates the migrations from the repo:
     - the sanitized live-schema snapshot `supabase/proposed/tests/live_snapshot_2026-09-29.json` (schema only, no user data);
     - **every package in `supabase/proposed/`, in the order listed in `setup.mjs` (`PACKAGES`)**.
   - Then it starts the project `tempa-local` (ports 554xx) and runs `db reset`. **That resets only YOUR local database, which starts empty.**
   - It also writes `.env.local-backend.local` (git-ignored).
   - Package order, which becomes local migrations 10 → 31; the last ones are:
     - `…027` connection answers;
     - `…028` versions;
     - `…029` intention / priorities (D104b);
     - `…030` Edit profile Package 1 (D105);
     - `…031` Recently (D106).
2. `node scripts/local-backend/seed.mjs` — synthetic accounts only (`@tempa-test.example.com`).
3. Optional smoke tests on real local services, e.g.:
   - `node scripts/local-backend/smoke_member_profile_edit_local.mjs`
   - `node scripts/local-backend/smoke_profile_recently_local.mjs`
4. `scripts/local-backend/start-app.sh <synthetic email>`
   - Starts Metro for the dev client with `TEMPA_BACKEND=local` and your Mac's Wi-Fi address.
   - Prints a one-time sign-in code. The phone must be on the same Wi-Fi.

Full command list, guards and the account-switch rules: [`TEST_ENVIRONMENT.md`](TEST_ENVIRONMENT.md) §A.

**Rules:**
- Never point anything at the shared project `fyqwjduzpnjuxqsloxih` (DEV = live).
- Don't run `apply-dev.mjs`.
- Synthetic accounts only.
- On a backend that already has data, apply new packages with `psql` in one transaction, as the owner does. Run `setup.mjs` only for a fresh, empty start.

### Environment variables (names only — values are generated locally or set by the scripts)

- **App (`app.config.js`):**
  - `TEMPA_BACKEND` (`local` / `dev` / `test` / `live`; no default — the app refuses to start without it);
  - `TEMPA_LOCAL_SUPABASE_URL`, `TEMPA_LOCAL_SUPABASE_ANON_KEY`;
  - `TEMPA_DEV_TEST_EMAIL`;
  - `TEMPA_TEST_SUPABASE_URL`, `TEMPA_TEST_SUPABASE_ANON_KEY`;
  - `EAS_BUILD_PROFILE` (production builds are pinned to live).
- **Generated by `setup.mjs`** into `.env.local-backend.local`: `LOCAL_SUPABASE_URL`, `LOCAL_SUPABASE_ANON_KEY`, `LOCAL_SUPABASE_SERVICE_ROLE_KEY`, `LOCAL_DB_URL`, `LOCAL_MAIL_URL`.
- **Unused cloud test project** (`scripts/test-backend/env.example`): `TEST_SUPABASE_URL`, `TEST_SUPABASE_ANON_KEY`, `TEST_SUPABASE_SERVICE_ROLE_KEY`, `TEST_DB_URL`.
- Never commit `.env*`, `.test-backend/`, sign-in codes, tokens or keys. They are git-ignored; keep it that way.

## 4. The phone app

The app is an Expo **development client** (`eas.json` profile `development`, internal distribution). To install it on your iPhone:
- the owner's Apple team must register your device (`npx eas device:create`), then build a new development client;
- or the owner adds you to the Expo project.

There is no simulator build profile yet. Adding one is a config change, not done.

Without your own build, the options are:

| Option | Works for | Limits |
|---|---|---|
| **A. Your own tempa-local + your own dev build** | full development and testing | Docker, device registration, a new build |
| **B. The owner's Mac on the same Wi-Fi** | trying the owner's local data on your phone (with a dev build installed) | only while the owner's Mac runs Metro + tempa-local, same network; the owner's synthetic accounts |
| **C. Design without running the app** | branding / UI / UX | screenshots or recordings from the owner's phone; the DEV design previews (`app/dev/*-preview`, local sample data, in Settings → "Developer (DEV only)") shown by the owner; mockups |
| **D. A shared cloud test project** | both working on one backend | doesn't exist; needs a decision (cost, data rules) — the shared DEV project is also live, so it is **not** an option |
